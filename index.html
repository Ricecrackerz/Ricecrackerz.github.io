Paddle Pal · How it's built

  • The rules live in code, not the prompt. Parameterized SQL, a whitelist of sortable columns, a five-row cap and a source label on every number. The model can ask for anything; the tools decide what comes back.
  • Not found beats a confident guess. A paddle the table doesn't have used to fuzzy-match to a different paddle that shared the words "16mm elongated." Now a match must contain every distinctive word you typed, and a miss is said out loud.
  • Missing is NULL, never zero. A paddle with no price stored as 0 would win every "under $200" question, and one with no power numbers would look "similar" to everything. Both are guarded, with tests.
  • Measured before it's kept. Evals written before the code ran score tool choice, facts cited and honest "not covered" answers. Indexing page titles took direct retrieval from 8 to 12 of 15 at hit@1.
  • The data owner's terms are code. The tester's export never enters git, no table dumps, no affiliate columns, and he can upload his next export himself behind an admin account, with a preview of every change.
